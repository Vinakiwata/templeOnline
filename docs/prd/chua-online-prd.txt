Chùa Online — Product Requirement Document (PRD) & Technical Architecture

Phiên bản: 1.0 — Product Foundation
Định hướng: 3D Virtual Buddhist Temple
Nền tảng: Responsive Web, Mobile-first
Đối tượng: Phật tử và người muốn tìm hiểu Phật giáo
Mô hình: Miễn phí, ưu tiên phát triển cộng đồng

Tôi sẽ thiết kế Chùa Online theo hướng một không gian chùa 3D trực tuyến, nơi người dùng có thể bước vào chùa, tự do khám phá, lễ bái, đọc kinh, thiền định và kết nối với cộng đồng.

Với lựa chọn 3D chân thực, sản phẩm cần được xem như một dự án kết hợp giữa:

Web application.

3D interactive experience.

Virtual world.

Buddhist cultural content platform.

Community platform.

Điều này ảnh hưởng trực tiếp đến kiến trúc React, game engine, hiệu năng trên mobile và cách tổ chức dữ liệu.

4.2. High-level Architecture
Architecture principle

Frontend không được phụ thuộc trực tiếp vào database.

Luồng dữ liệu:

React UI → Application Service → API → Backend Service → Database

Riêng hoạt động 3D:

Player Input → Game Interaction System → Application Event → React UI / Backend

Các hành động trong game không nên gọi API trực tiếp từ từng mesh hoặc component 3D.

5.3. Interaction System

Không nên hardcode từng hành động vào từng object 3D. Hãy xây dựng một hệ thống tương tác dùng chung.

Ví dụ:

Tượng Phật có thể lễ bái.

Bàn hoa có thể dâng hoa.

Chuông có thể thỉnh chuông.

Kinh sách có thể mở thư viện.

Khu thiền có thể bắt đầu thiền định.

Interaction architecture
Interface đề xuất
export type InteractionAction =
  | "worship"
  | "offer_flower"
  | "light_incense"
  | "ring_bell"
  | "read_sutra"
  | "meditate";

export interface Interactable {
  id: string;
  type: string;
  name: string;
  position: [number, number, number];
  actions: InteractionAction[];
}

Đối tượng 3D chỉ cần cung cấp thông tin tương tác. Logic xử lý sẽ nằm trong Interaction System.

Ví dụ:

const buddhaStatue: Interactable = {
  id: "buddha-main-hall",
  type: "buddha_statue",
  name: "Tượng Phật Thích Ca",
  position: [0, 0, 0],
  actions: ["worship", "offer_flower"],
};

Trong production, nên bổ sung các interface cho metadata, interaction radius, điều kiện hiển thị và trạng thái đối tượng.

7.2. Guest User

Guest mode là một yêu cầu quan trọng của sản phẩm.

Có thể triển khai:

Guest session được tạo phía client.

Guest có thể trải nghiệm 3D.

Hoạt động cơ bản không cần đăng nhập.

Khi đăng ký, hệ thống có thể cho phép chuyển guest progress sang account.

Guest session không nên được xem là danh tính đã xác thực. Các hoạt động nhạy cảm như quyên góp, quản lý tài khoản và tương tác có quyền riêng tư phải yêu cầu xác thực phù hợp.

Vì sao dùng monorepo?

Frontend và backend dùng chung TypeScript types.

Game configuration có thể chia sẻ.

Dễ quản lý API contract.

Thuận tiện cho CI/CD.

Hỗ trợ phát triển nhiều ứng dụng sau này.

Tuy nhiên, nếu MVP chỉ có một frontend và backend nhỏ, có thể bắt đầu bằng hai project riêng. Monorepo không phải yêu cầu bắt buộc.

Tránh lỗi phổ biến

10. 3D Performance Architecture — Ưu tiên Mobile

Đây là rủi ro kỹ thuật lớn nhất của Chùa Online.

Bạn muốn 3D chân thực, nhưng người dùng sẽ truy cập bằng điện thoại, bao gồm các thiết bị có GPU và bộ nhớ hạn chế.

Three.js có hướng dẫn riêng về responsive rendering và xử lý màn hình high-DPI. Đặc biệt, render ở độ phân giải quá cao có thể làm tăng đáng kể tải GPU trên mobile.

10.3. Các kỹ thuật tối ưu

Giới hạn devicePixelRatio.

Giảm số lượng draw calls.

Sử dụng instanced rendering cho các vật thể lặp.

Dùng texture atlas khi phù hợp.

Hạn chế real-time shadow.

Dùng baked lighting cho kiến trúc chùa.

Culling vật thể ngoài camera.

Load asset theo khu vực.

Dùng LOD cho vật thể có nhiều mức chi tiết.

Tắt hoặc giảm animation khi tab không hoạt động.

Không render game khi scene đang bị ẩn nếu không cần thiết.

11. Security & Privacy

Chùa Online có tài khoản, lịch sử hoạt động và có thể có cộng đồng. Vì vậy cần thiết kế bảo mật ngay từ đầu.

11.1. Security requirements

HTTPS.

Authentication.

Authorization.

Input validation.

Rate limiting.

XSS protection.

CSRF protection nếu sử dụng cookie-based authentication.

API validation.

Không lưu password dạng plaintext.

Không đưa secret vào frontend.

Kiểm soát quyền admin.

Bảo vệ dữ liệu cá nhân.

11.2. Guest security

Guest mode cần tránh:

Giả mạo user ID.

Gửi request hoạt động hàng loạt.

Tạo dữ liệu giả trong community.

Lạm dụng API.

Guest nên có session ID ngẫu nhiên, giới hạn rate và không có quyền thực hiện các hành động nhạy cảm.

11.3. Community moderation

Cần chuẩn bị:

Report user.

Block user.

Kiểm duyệt nội dung.

Quản lý bình luận.

Chặn spam.

Quy định cộng đồng.

Quy trình xử lý nội dung xúc phạm tôn giáo.

Với nội dung Phật giáo, moderation không chỉ xử lý spam mà còn cần bảo vệ sự tôn trọng giữa các truyền thống và người dùng.
